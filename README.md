# Interactive Game Systems Code Map

실물 타격 장치 하나를 격투게임과 리듬게임이라는 서로 다른 플레이 경험으로 연결하면서, 제작 도구·BLE 진단·포즈 데이터·게임 서버 연동 과정에서 해결한 문제를 정리한 포트폴리오입니다.

완성 제품이나 사내 원본 기술을 공개하는 저장소가 아닙니다. 공개 가능한 범위에서 **어떤 필요가 있었고, 무엇을 직접 설계·구현했으며, 기존 코드와 외부 기술을 어떻게 수정·통합했는지**에 초점을 맞춥니다.

## 하나의 장치, 두 가지 플레이 규칙

### 격투게임: 자세와 실제 타격을 함께 판정

격투게임은 BLE 입력만으로 공격을 판정하지 않았습니다. 카메라에서 추출한 MediaPipe 관절 데이터로 발차기 자세·방향·높이를 해석하고, 동시에 장치의 어느 위치가 실제로 타격되었는지를 수신했습니다.

`카메라 포즈 데이터 + BLE 타격 위치 → 상·중·하단 공격 결과`

이를 위해 Python·Linux·Web 환경에서 카메라 인식과 관절 추출을 비교했고, 실제 확인 결과 움직임과 좌표 추출이 가장 안정적이었던 Web 방식을 선택했습니다. Web 설정 UI, 카메라 선택, 30/60 FPS 모드, 랜드마크 JSON 변환, 좌표 스케일, 목적지 IP·포트, 두 포트 전송, Node.js 중계 서버와 Windows 실행 파일 패키징을 구현했습니다.

Unity에서는 여러 공개 리깅 구현을 비교하며 관절 번호와 본 매핑, 좌표계 변환, Quaternion 회전, 보간과 떨림 감소 방식을 검증했습니다. 최종 수신부는 상급자가 수정했을 가능성이 있어, 개인 기여는 제가 확인할 수 있는 구현·검증 범위로 한정합니다.

### 리듬게임: 상·중단 4개 입력과 음악 타이밍을 연결

리듬게임은 동일 장치에서 좌·우 상단과 중단의 4개 위치를 사용했습니다. 화면의 네 방향 노트와 실제 타격 입력을 연결해 2인 플레이가 가능하도록 구성했습니다.

입력 연결 이후에는 별도의 제작 문제가 남았습니다. 기존 채보는 음악을 재생하며 4개 레인에 대응하는 키 입력을 실시간으로 녹화하고, 각 입력 시점을 `float` 절대 시간으로 저장하는 방식이었습니다. 빠른 초안 제작에는 적합했지만 사람의 반응 시점이 기록 기준이어서 박자 오차가 생길 수 있었고, 음악의 박자 구조를 기준으로 수정하기 어려웠습니다. 이를 BPM·오프셋·박자 단위 데이터로 바꾸자고 제안하고, Unity EditorWindow와 인게임 노트 스폰 방식을 전부 구현했습니다.

결과적으로 채보 제작과 수정이 입력 시점이 아닌 같은 음악 기준을 중심으로 이루어지게 했으며, 단순한 제작 시간 단축보다 **노트 타이밍의 기준을 음악의 박자 체계로 통일한 것**이 핵심 개선입니다.

## 공통 기반: BLE 연결과 6개 입력 진단

기존 사내 `jcBLE` 코드를 전달받았지만 그대로 연결만 한 것은 아닙니다. 실제 빌드 앱과 안정적으로 연동되도록 내부 코드를 수정하고, 연결 씬에 필요한 기능과 UI는 직접 구현했습니다.

- 장치 검색·연결·해제·재검색
- Characteristic 구독과 재연결 흐름
- 연결 성공 시 초록 상태 표시
- 2열 × 3단 여섯 위치의 입력 상태 시각화
- 타격 입력 수신 시 해당 위치를 빨간색으로 점등
- 격투게임의 6개 입력과 리듬게임의 상·중단 4개 입력을 동일 진단 화면에서 확인

`BluetoothLEHardwareInterface`는 Asset Store 플러그인이며, 저수준 BLE 통신 플러그인 자체를 제 구현으로 주장하지 않습니다.

## 서버 연동

DBServer에서는 HNetwork의 공개 네트워크 API를 사용해 Unity의 로그인·계정·랭킹·플레이 기록 요청을 서버와 DB 처리 흐름에 연결했습니다. 요청 분기, 작업 큐·워커, ODBC 연결 풀을 포함한 응용 연동을 담당했고, 이후 상급자가 제 코드를 다듬었습니다.

HNetwork 자체나 저수준 네트워크 라이브러리를 개발한 것이 아니라, 제공된 API를 실제 Unity 기능으로 완성하는 연동 범위가 개인 기여입니다.

## 기여 경계

### 직접 설계·구현

- BPM 기반 채보 방식 제안, 데이터 구조, Unity EditorWindow, JSON 입출력, 인게임 BPM 스폰
- BLE 연결 씬 전체 UI와 검색·연결·상태·입력 진단 흐름
- MediaPipe Web 설정 UI, 랜드마크 데이터 가공, Node.js 중계와 패키징
- Unity가 사용하는 서버 요청과 DB 응용 기능 연동

### 기존 코드 기반 수정·통합

- 사내 `jcBLE` 연결 모듈을 실제 빌드와 UI 상태 흐름에 맞게 수정
- Google MediaPipe 예제를 카메라 설정과 Unity 전송 목적에 맞게 확장
- 공개 Unity 리깅 사례를 비교하며 본 매핑·좌표·회전·보간 방식 검증
- HNetwork 공개 API 위에 서버 응용 흐름 구성

### 본인 구현으로 주장하지 않는 항목

- 저수준 BLE 플러그인
- HNetwork 네트워크 라이브러리
- Google MediaPipe 관절 추론 모델
- 자세 분류 모델의 학습 로직
- 외부 Unity 에셋
