# Interactive Game Systems Code Map

실물 입력 장치와 Unity 게임을 연결하는 과정에서 해결한 문제들을 정리한 시스템 통합 포트폴리오입니다.

리듬게임 채보 제작, BLE 장치 진단, MediaPipe 관절 데이터 전달, C++ 게임 서버 연동이라는 서로 다른 작업을 하나의 기준으로 설명합니다. 완성된 제품을 소개하기보다 **왜 이 기능이 필요했고, 어떤 문제를 발견했으며, 무엇을 직접 설계·구현했는지**에 초점을 맞췄습니다.

## 핵심 문제 해결

### 감각적인 시간 기록을 음악적인 기준으로 전환

기존 리듬게임 채보는 노트가 떨어질 시점을 `float` 시간값으로 직접 기록했습니다. 이 방식은 작업자의 감각에 따라 결과가 달라졌습니다. BPM과 음악 오프셋을 공통 기준으로 삼는 제작·재생 구조를 제안하고, 비개발자도 사용할 수 있는 Unity 편집 도구로 연결했습니다.

### 통신 성공과 실제 입력 정상을 분리해 진단

BLE가 연결됐다는 사실만으로 장치의 모든 입력이 정상이라고 볼 수 없었습니다. 장치 검색과 연결 상태는 목록·색상으로 표현하고, 실제 타격 입력은 위치별 표시가 순간적으로 점등되도록 구성해 두 문제를 한 화면에서 구분할 수 있게 했습니다.

### 실행 환경을 직접 비교하고 전달 파이프라인 구성

MediaPipe의 Python, Linux, Web 방식을 실제 카메라 입력으로 비교했습니다. 수치 벤치마크가 아닌 호환성, 움직임 연속성, 시각적 떨림과 좌표 안정성에 대한 정성적 검증이었으며, 최종적으로 Web 방식을 선정했습니다. 이후 카메라·프레임 설정, 좌표 가공, 로컬 서버 전송과 Unity 리깅 실험까지 연결했습니다.

### 공개 API를 게임 기능으로 완성

C++ 서버에서는 오픈 소스 네트워크 API 자체를 개발한 것이 아닙니다. 제공된 통신 API 위에 Unity 요청을 분기하고 DB 작업을 처리하는 응용 계층을 구현했습니다. 이후 상급자가 코드를 보완했으므로 개인 기여는 최초 구현과 연동 범위로 한정해 기술합니다.

## 기여 범위

### 직접 설계·구현

- BPM 기반 채보 방식, Unity EditorWindow와 인게임 노트 타이밍
- BLE 연결 화면 전체 UI와 검색·연결·상태·입력 진단 흐름
- MediaPipe Web 설정 UI, 랜드마크 데이터 가공과 Node.js 중계 서버
- Unity 클라이언트와 C++ DB 서버의 응용 기능 연동

### 기존 코드 기반 수정·통합

- 인계받은 사내 BLE 연결 모듈을 실제 빌드와 UI 상태 흐름에 맞게 수정
- Google MediaPipe 예제를 카메라 설정과 Unity 전달 목적에 맞게 확장
- 공개 Unity 리깅 사례를 비교하며 본 매핑, 좌표계, Quaternion과 보간 방식 검증
- HNetwork의 공개 API를 이용한 서버 응용 계층 구성

### 본인 구현이 아닌 항목

- 저수준 BLE 통신 플러그인
- HNetwork 네트워크 라이브러리
- Google MediaPipe의 관절 추론 모델
- 포즈 분류 모델의 학습 로직
- 제3자 Unity 에셋

## 공개 데모

`Demo Lab`의 코드는 회사 원본을 옮긴 것이 아니라, 당시 해결한 문제와 동작 원리를 설명하기 위해 공개용으로 새로 작성한 구현입니다.

- **BPM Chart Demo**: BPM·오프셋 설정, 비트 그리드 편집, 재생, JSON 미리보기와 내보내기
- **Virtual BLE Diagnostics**: 가상 장치 검색·연결·해제, 채널 입력과 상태 점등

실제 장치가 없어도 브라우저에서 핵심 작업 흐름을 확인할 수 있습니다.
