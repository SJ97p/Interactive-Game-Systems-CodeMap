# BPM 기반 리듬게임 채보 시스템

## 필요했던 이유

기존 채보는 음악을 재생한 상태에서 개발자가 4개 레인에 대응하는 키를 실시간으로 입력하면, 시스템이 각 입력 시점을 `float` 형태의 절대 시간으로 저장하는 녹화 방식이었습니다. 빠르게 초안을 만들 수 있다는 장점은 있었지만, 사람의 반응 시간과 키 입력 타이밍이 기록 기준이어서 노트가 박자에서 미세하게 벗어날 수 있었습니다. 또한 음악의 BPM이나 박자 구조가 데이터에 직접 표현되지 않아, 잘못 배치된 노트는 개별 시간값을 다시 조정해야 했습니다.

## 문제 정의

핵심 문제는 단순한 편집 UI의 부재가 아니라, 실시간 키 입력의 기록 시점이 곧 채보 기준이 되고 음악의 박자 체계가 데이터에 표현되지 않는다는 점이었습니다. 이에 입력 시점 중심 방식을 BPM과 음악 오프셋 중심의 제작·재생 구조로 전환할 것을 제안했습니다.

## 해결 과정

- 음악별 BPM, 오프셋, 활성 레인과 채보 파일을 관리하는 데이터 구조를 구성했습니다.
- Unity `EditorWindow`에서 곡과 JSON 채보를 선택하고 레인별 노트를 편집할 수 있도록 구현했습니다.
- 음악 재생 중 4개 레인 키 입력의 레인과 시점을 녹화하고, 편집 결과를 JSON으로 내보내도록 구성했습니다.
- BPM을 기준으로 편집 화면의 시간·박자 간격을 표현했습니다.
- 인게임 노트 출력도 실시간 키 입력으로 기록된 절대 시간에만 의존하지 않고 BPM 단위의 타이밍을 기준으로 동작하도록 수정했습니다.

## 결과

노트 배치가 음악 박자에 더 일관되게 맞도록 개선됐습니다. 녹화된 입력 시점이 아닌 BPM과 Beat를 기준으로 채보를 수정할 수 있게 되어, 반복 제작에서 타이밍을 해석하고 수정하는 기준을 통일했습니다.

정확한 제작 시간이나 오차율을 별도로 측정하지 않았으므로 수치 개선으로 표현하지 않습니다. 핵심 성과는 실시간 키 입력 녹화 시점 중심의 채보 기준을 음악의 BPM 체계로 전환하고, 비개발자도 수정할 수 있는 제작 흐름으로 만든 것입니다.

## 개인 기여

- 문제 발견과 BPM 방식 전환 제안
- 데이터 구조와 제작 흐름 설계
- Unity EditorWindow 및 채보 편집 기능 전체 구현
- JSON 채보 입출력과 레인별 기록 기능 구현
- BPM 기반 인게임 노트 타이밍 방식 구현
- 다른 두 작업자가 사용할 수 있도록 도구화

## 공개 범위

회사 원본 프로젝트, 음원, UI, 채보 데이터는 공개하지 않습니다. 공개 데모는 저작권 문제가 없는 임시 음원 또는 메트로놈과 새로 작성한 코드로 재구성합니다.
