# MediaPipe–Unity 실시간 관절 데이터 연동

## 필요했던 이유

카메라로 사용자의 움직임을 추적해 Unity 캐릭터에 반영하고 자세를 판정하려면, 관절 데이터를 안정적으로 추출하고 게임으로 전달하는 파이프라인이 필요했습니다. 실행 언어와 환경에 따라 지원 프레임과 관절 추출 품질이 달랐기 때문에 하나의 방식을 바로 채택할 수 없었습니다.

## 기술 검증

Python, Linux, Web 환경에서 카메라 인식, 30/60FPS 구동, 움직임 연속성과 관절 좌표 안정성을 직접 확인했습니다. Linux 환경에서는 60FPS 구동이 가능했지만 관절 추출 품질이 요구 수준에 미치지 못했습니다. 정성적 비교 결과 Web 방식이 움직임을 가장 부드럽게 인식하고 좌표를 안정적으로 추출해 최종 방식으로 선택했습니다.

정확한 수치 측정을 수행한 성능 벤치마크는 아니며, 실제 동작을 기준으로 한 기술 검증과 선정 과정입니다.

## 해결 과정

- Google MediaPipe 웹 예제를 회사 사용 흐름에 맞게 개조했습니다.
- 회사 로고 및 설정 화면, 카메라 장치 선택, 30/60FPS 모드를 구성했습니다.
- 목적지 IP와 포트를 입력하고 설정 완료 후 추적 화면으로 이동하도록 구현했습니다.
- 관절 좌표를 수신 측이 사용할 JSON 형식으로 가공하고 필요한 스케일 변환을 적용했습니다.
- Node.js/Express 중계 서버를 구현했습니다.
- 웹에서 받은 데이터를 실시간 전송 방식으로 Unity에 전달했습니다.
- 동일한 관절 데이터를 캐릭터 리깅과 자세 판정에서 독립적으로 소비할 수 있도록 전달 경로를 분리했습니다.
- 웹 소스를 먼저 난독화한 뒤 Windows 실행 파일로 패키징했습니다. 당시 사용한 난독화 도구명은 확인되지 않아 특정하지 않습니다.

## Unity 리깅 검증

여러 공개 MediaPipe–Unity 프로젝트를 분석해 JSON 파싱, 관절 번호와 캐릭터 본 매핑, 좌표계 변환, Quaternion 회전 계산, 보간과 떨림 감소 방식을 비교·적용했습니다. 이 과정에서 캐릭터가 과도하게 흔들리거나 비정상적으로 변형되지 않는 방식을 검토했습니다.

Unity 수신부 일부를 개발했지만 이후 상급자가 코드를 수정했고 본인 버전의 최종 채택 여부는 확인되지 않았습니다. 따라서 이 부분은 최종 상용 구현이 아니라 기술 검증 및 프로토타이핑 경험으로 구분합니다.

## 자세 분류 관련 범위

MediaPipe 관절 데이터를 이용해 발차기 종류와 높이를 분류하는 학습 과정에도 참여했으나, 학습 로직 자체는 다른 작업자의 구현입니다. 본인은 학습용 데이터 이미지 편집을 지원했으며 모델 개발자로 표현하지 않습니다.

## 결과

여러 실행 환경을 실제로 검증해 프로젝트에 적합한 Web 방식을 선택하고, 카메라 입력부터 데이터 가공, Unity의 리깅 및 자세 판정 경로로 전달하는 실행 도구를 구성했습니다.

## 공개 범위

회사 로고, 제품명, 실제 목적지 정보, 내부 데이터 포맷과 원본 실행 파일은 공개하지 않습니다. Google 예제를 활용한 부분과 직접 확장한 부분을 공개 데모에서 명확히 구분합니다.
